Before asking whether a quantum algorithm is faster, we must specify what a quantum computation is, how it receives its input, and which resource is being measured. This chapter develops that language.

Formal foundation18–22 minute readAssumes discrete mathematics

What mathematics will this project use?

We assume the standard 15-455 background: asymptotic notation, polynomial-time computation, randomized algorithms and bounded error, reductions, and basic probability. We also use bitwise XOR, dot products modulo 2, and Gaussian elimination over 𝔽2; these ideas are reviewed when first needed. The next two chapters introduce all required quantum notation, so no prior physics or quantum-computing course is assumed.

1. Why study a quantum model?

Recall that a classical computation stores information in bits and updates those bits by applying logical operations. A quantum computation replaces both ingredients: information is represented by a quantum state, and the state evolves through operations constrained by quantum mechanics. Thus the distinction is not merely one of speed; it is a change in the underlying computational model.

That change does not make every problem easier. In particular, a superposition is not an exponentially long list that can be read at the end of the computation. Any advantage must be engineered through interference, so that the amplitudes associated with useful global structure reinforce while irrelevant alternatives cancel.

Guiding Question

Can a quantum algorithm solve a problem using substantially fewer accesses to its input than any classical algorithm?

Simon’s problem gives a particularly clean affirmative answer. Its quantum solution makes only linearly many oracle queries, whereas every bounded-error classical randomized algorithm needs exponentially many. To understand why this statement is meaningful—and exactly what it does and does not claim—we first need a precise model and a precise resource measure.

2. Computation begins with a model

Every complexity claim is relative to a model of computation. Classical complexity theory may use Turing machines, RAM machines, or uniform Boolean circuits; for polynomial-time questions these standard models are interchangeable up to polynomial overhead. The model still matters, however, because it tells us which operations count as elementary.

We will use the uniform quantum circuit model. On unary input 1n, a classical polynomial-time procedure produces a finite circuit Cn. That circuit acts on n input qubits and polynomially many auxiliary qubits initialized to |0⟩, applies gates from a fixed finite universal set, and finally measures designated output qubits in the computational basis.

Definition 1 (Quantum circuit, informal)

A quantum circuit on k qubits is a finite sequence U1, …, UT of unitary gates, where each gate acts on a constant number of the k qubits. On initial state |ψ0⟩, its pre-measurement state is UT ··· U1|ψ0⟩. A specified measurement maps this state to a classical output distribution.

Remark 2 (Physical hardware versus computational model)

Uniformity prevents a circuit family from hiding an uncomputable amount of advice in its circuits. Real devices must additionally contend with noise, geometry, and fault tolerance; the ideal circuit model abstracts away those engineering constraints.

3. The query complexity viewpoint

We now need to say how the circuit receives its input. Suppose the input is a function f : {0,1}n → {0,1}m. Its complete truth table contains 2nm bits, so charging the algorithm merely for reading that table would conceal the information-theoretic phenomenon of interest. We therefore expose f through a black-box oracle and count how often the algorithm calls it.

Definition 3 (Query complexity)

Fix a class of allowed inputs ℱ and a target function g : ℱ → S. The deterministic query complexity D(g) is the least T for which a deterministic algorithm outputs g(f) after at most T oracle calls, for every f ∈ ℱ. The bounded-error randomized and quantum query complexities, Rε(g) and Qε(g), are defined analogously, except the algorithm must be correct with probability at least 1 − ε on every valid f.

Unless stated otherwise, we set ε = 1/3. Any fixed ε ∈ (0,1/2) leads to the same asymptotic notion after standard error reduction. Computation between oracle calls is treated as free, not because it is free in practice, but because this convention isolates the information cost of accessing f.

Remark 4 (Worst-case convention)

The query bound and success condition are worst-case over valid inputs. Probability is only over the algorithm’s internal random bits or quantum measurement outcomes—not over a distribution on oracle functions.

Classical and quantum access

A classical query chooses an input x and receives f(x). A quantum query provides coherent access to the same function, allowing later interference to reveal global structure. After introducing quantum states and gates, Chapter 3 will define this access precisely and explain why the oracle must be reversible.

4. What counts as a quantum speedup?

With the model and resource fixed, we can finally state what a speedup means. An upper bound such as Q1/3(gn) = O(n) describes one quantum algorithm. A separation requires more: a lower bound against every algorithm in the competing classical model.

  • A polynomial speedup might compare Q(n) = O(√n) with C(n) = Ω(n).
  • An exponential speedup might compare Q(n) = O(n) with C(n) = Ω(2n/2).

The qualifiers matter. “Quantum is faster” is incomplete unless we name the problem, computational models, resource, and error guarantee. A query separation does not by itself imply an end-to-end runtime separation.

Guiding Question

If oracle queries are not the only operations an algorithm performs, why is a query separation still meaningful?

It establishes that the quantum model can extract information in a way the classical model cannot match with the same number of oracle calls. But query complexity is not the same as total runtime, and an oracle problem is not automatically a practical application. We will keep those limitations explicit.

5. The road to Simon’s algorithm

Definition 5 (Promise problem)

A promise problem is a pair (LYES, LNO) of disjoint languages. An algorithm must accept every input in LYES and reject every input in LNO; its behavior outside LYES ∪ LNO is unrestricted. A search promise problem similarly requires a valid output only on promised inputs.

We can now preview the problem that will occupy the rest of the course. Simon’s problem is a search promise problem: we receive oracle access to f : {0,1}n → {0,1}n and are promised that there is a unique nonzero s ∈ {0,1}n such that, for all x, y ∈ {0,1}n,

f(x) = f(y)  ⇔  y ∈ {x, x ⊕ s}.

The equivalence implies that f is exactly two-to-one and its collision pairs are {x, x ⊕ s}. A classical algorithm learns s from a collision, since s = x ⊕ y. Under fewer than order 2n/2 queries, a collision occurs with only small probability, while sampling order 2n/2 distinct inputs finds one with constant probability by a birthday-paradox argument. Hence R1/3(Simonn) = Θ(2n/2).

The quantum algorithm avoids searching for a collision. Each oracle call, together with interference and measurement, yields a uniformly random z satisfying the linear equation z · s = 0 over 𝔽2. After O(n) repetitions, these equations span the (n − 1)-dimensional subspace orthogonal to s with constant probability, and Gaussian elimination over 𝔽2 recovers s. Thus Q1/3(Simonn) = O(n).

This summary already contains the whole strategy, but it compresses several ideas—superposition, relative phase, interference, tensor-product states, and measurement—into a few words. The next chapter develops those ideas carefully before we return to the algorithm.

Takeaway

For bounded error, Simon’s problem satisfies Q1/3(Simonn) = O(n) while R1/3(Simonn) = Θ(2n/2). These bounds give an exponential quantum query separation for a promise problem.
