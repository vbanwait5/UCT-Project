Chapter 04

Simon’s Problem

The problem is a carefully structured search task over the vector space 𝔽2n. Its promise turns collisions into equations about one hidden XOR mask.

Promise problem18–22 minute readIncludes coset explorer

1. Formal statement

Definition 1 (Simon’s search problem)

Input: oracle access to a function f : {0,1}n → {0,1}n, satisfying the promise that there exists a unique nonzero s ∈ {0,1}n such that, for all x,y,

f(x) = f(y)  ⇔  y ∈ {x, x ⊕ s}.

Output: the hidden string s.

The biconditional is essential. It says both that x and x ⊕ s collide and that there are no other collisions. Therefore every value in the image has exactly two preimages. The function’s detailed labels are arbitrary; only its pairing structure matters.

Remark 2 (Promise versus language)

The algorithm is required to succeed only on functions satisfying the promise. On a one-to-one function, a function with larger fibers, or a noisy approximation, its output need not have any meaning.

2. The algebra hiding under XOR

Identify {0,1}n with the vector space 𝔽2n. Vector addition is bitwise XOR. Every element is its own additive inverse, so x ⊕ s ⊕ s = x.

The set H = {0n, s} is a two-element subgroup of 𝔽2n. The promise says exactly that f is constant on each coset x + H = {x, x ⊕ s} and takes different values on different cosets.

Proposition 3 (Uniqueness)

If s ≠ 0n satisfies Simon’s promise, then it is unique.

Proof. If both s and t satisfy the promise, then f(0n) = f(s) implies s ∈ {0n, t}. Since s is nonzero, s = t. ∎

3. Fibers are cosets

A fiber f−1(a) is the set of inputs mapped to output a. Simon’s promise partitions the 2n inputs into 2n−1 disjoint fibers of size two. This quotient-space viewpoint is the first appearance of the hidden subgroup framework.

𝔽2n / H = {x + H : x ∈ 𝔽2n}.

The oracle hides H by labeling its cosets injectively. The task is not to learn the labels but to recover the subgroup generator s.

Connection: equivalence relations and quotients

The relation x ~ y iff f(x) = f(y) is an equivalence relation. Under the promise, its equivalence classes are exactly the cosets of H. The algorithm learns the partition’s symmetry without learning its arbitrary labels.

5. Search, decision, and verification

Simon’s task is a search problem: output an n-bit witness s. Given a candidate s, one can test the identity f(x) = f(x ⊕ s) on sampled inputs, but black-box verification on every input would itself be expensive.

A related decision version asks whether f is one-to-one or satisfies the two-to-one Simon promise. The search and decision versions are closely related but not definitionally identical. When making a complexity claim, we must say which version and which input promise we mean.

Connection: reductions and completeness

Reductions between promise problems must map promised yes/no instances to promised instances. A reduction that sends valid inputs outside the target promise does not establish correctness. Simon’s problem is an important algorithmic primitive, but it is not known to be complete for BQP.

6. What does one classical query reveal?

A response f(x) is merely an opaque label until the same label appears again. If all observed outputs are distinct, many choices of s remain consistent with the transcript. In contrast, a collision f(x) = f(y) immediately determines s = x ⊕ y.

This all-or-nothing behavior is the heart of the randomized lower bound. The quantum algorithm will avoid waiting for a visible collision: it converts the pairing symmetry into equations z · s = 0.

Takeaway

Simon’s oracle hides the subgroup H = {0,s} by assigning a distinct label to each coset. Classical access exposes labels; quantum interference exposes characters that are trivial on H.
