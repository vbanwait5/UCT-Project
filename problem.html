Chapter 04

Simon’s Problem

Every input has one hidden partner. The same XOR string connects every pair, and the goal is to recover that string.

Promise problem12–15 minute readIncludes pair explorer

1. Formal statement

Definition 1 (Simon’s search problem)

Input: oracle access to a function f : {0,1}n → {0,1}n, satisfying the promise that there exists a unique nonzero s ∈ {0,1}n such that, for all x,y,

f(x) = f(y)  ⇔  y ∈ {x, x ⊕ s}.

Output: the hidden string s.

The biconditional carries both halves of the promise. It guarantees that x and x ⊕ s receive the same output, and it rules out every other collision. Consequently, each value in the image has exactly two preimages. The bit patterns used as output labels are arbitrary; all of the relevant information lies in the induced pairing of inputs.

Remark 2 (Promise versus language)

The algorithm is required to succeed only on functions satisfying the promise. On a one-to-one function, a function with larger fibers, or a noisy approximation, its output need not have any meaning.

2. The XOR arithmetic we need

Bitwise XOR adds corresponding bits modulo 2: 0⊕0=0, 0⊕1=1, 1⊕0=1, and 1⊕1=0. For example, 011⊕101=110. Because a bit XOR itself is zero, applying the same shift twice returns to the starting point:

x ⊕ s ⊕ s = x.

We sometimes call the set of n-bit strings 𝔽2n. In this project that notation means only that strings can be added using XOR. The two-element set H={0n,s} generates the pairs {x,x⊕s}.

We also use the binary dot product

z · s = z1s1 ⊕ ··· ⊕ znsn.

For example, 110·101 = (1·1)⊕(1·0)⊕(0·1)=1. The equation z·s=0 is therefore an ordinary linear equation in the unknown bits of s, with all arithmetic performed modulo 2.

Proposition 3 (Uniqueness)

If s ≠ 0n satisfies Simon’s promise, then it is unique.

Proof. If both s and t satisfy the promise, then f(0n) = f(s) implies s ∈ {0n, t}. Since s is nonzero, s = t. ∎

3. The hidden pairs

A fiber f−1(a) is simply the set of inputs that receive output a. Simon’s promise says that every fiber contains exactly the pair {x,x⊕s}. Thus the 2n inputs split into 2n−1 disjoint pairs.

These pairs are formally the cosets x+H of H={0,s}. We will use the phrase coset state later, but for Simon’s problem it means only an equal superposition of the two inputs in one hidden pair.

5. Search, decision, and verification

It is worth being precise about the type of computational task. Simon’s problem is a search problem: the required output is the n-bit string s. Given a candidate shift, one may test f(x) = f(x ⊕ s) on sampled inputs, but verifying that identity on the entire black-box domain would itself require many queries.

A related decision version asks whether f is one-to-one or satisfies the two-to-one Simon promise. The search and decision versions are closely related but not definitionally identical. When making a complexity claim, we must say which version and which input promise we mean.

Connection: reductions and completeness

Reductions between promise problems must map promised yes/no instances to promised instances. A reduction that sends valid inputs outside the target promise does not establish correctness. Simon’s problem is an important algorithmic primitive, but it is not known to be complete for BQP.

6. What does one classical query reveal?

We can already see why the classical problem is difficult. A response f(x) behaves like an opaque label until that same label is observed again. As long as all answers are distinct, many values of s remain consistent with the transcript. Once a collision f(x) = f(y) appears, however, the promise immediately gives s = x ⊕ y.

This sharp change—from almost no information to complete recovery—is the core of the randomized lower bound. The quantum algorithm follows a different route: instead of waiting to see a collision, it converts the same pairing symmetry into linear equations of the form z · s = 0.

Takeaway

Simon’s oracle hides the subgroup H = {0,s} by assigning a distinct label to each coset. Classical access exposes labels; quantum interference exposes characters that are trivial on H.
